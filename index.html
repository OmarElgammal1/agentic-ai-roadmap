agentic-ai-roadmap

Learning to build AI agents

The path I'd follow if I were starting today, from "what even is an agent" to running one in production. Almost everything here is free.

Put together by Omar Elgammal · last updated October 2026

How to use this

Go in order. Steps marked optional can be skipped without breaking anything later on.

Most steps end with a small build it task. Please actually do them. Watching a course feels like progress, but you only find out what you don't understand when you try to build something.

Every task ends with writing an Agent Skill: a folder with a SKILL.md file that teaches a coding agent how to do what you just learned. By the end you'll have a set of skills you can drop into Claude Code or any other tool that supports them, and writing them down is a good test of whether you really get it. There's a starter template in the skills folder of the repo, and step 4 covers how skills work properly.

Before touching any code, get a feel for what an agent is and isn't. Watch the three videos in order, then read the three pieces below them. That's a weekend, tops.

03

LangGraph & Deep Agents

LangGraph is the framework I'd learn first. It gives you control over state and flow, and the learning material around it is the best I've found. Deep Agents is LangChain's newer library on top of it, for long-running agents that plan, spin off sub-agents and work with files.

start here
LangGraph Complete Course for Beginnersmy pick
freeCodeCamp · YouTube · ~3 hours
You build five agents from scratch, including a RAG one. There's a companion repo, so code along instead of just watching.
then Deep Agents
Deep Agents overview
LangChain docs · GitHub
Planning tools, sub-agents, a virtual file system and long-term memory, packaged so you don't have to wire them up yourself. Read this once LangGraph feels comfortable.
Project: Deep Agentsoptional
LangChain Academy
A guided project if you'd rather build one end to end than read the docs.
optional, if you want more
Introduction to LangGraphoptional
LangChain Academy
Six modules on state, nodes, edges, memory and human-in-the-loop. Slower than the freeCodeCamp course, but it goes deeper.
Deep Research with LangGraphoptional
LangChain Academy
A multi-agent research system, evaluated with LangSmith.
Ambient Agents with LangGraphoptional
LangChain Academy
An always-on email agent. It's a good look at agents that run in the background instead of in a chat window.
build it Build a small LangGraph agent for something you actually do, like sorting your inbox or summarising papers. Then write a langgraph-scaffold skill describing how you set up a new graph: how you shape the state, where the tools live, which checkpointer you use and how you test it.
04

MCP & Agent Skills

These two ideas show up everywhere now. MCP is the standard way to give an agent tools and data. Skills are how you give it know-how: instructions, scripts and references it loads only when it needs them. Read the docs here rather than a third-party tutorial, because they're short and kept up to date.

model context protocol
What is MCP?
modelcontextprotocol.io
The official intro. Read about servers, clients, tools, resources and prompts, and you'll have most of it.
MCP: Build Rich-Context AI Apps with Anthropicoptional
DeepLearning.AI
A short course where you build an MCP server and client yourself.
FastMCPmy pick
gofastmcp.com
The easiest way to write MCP servers in Python. If you know FastAPI, a decorated function becomes a tool and it'll feel familiar. This is what you'll use in step 6.
agent skills
Equipping agents for the real world with Agent Skills
Anthropic Engineering
Why skills exist and how they load progressively, so the agent only reads what it needs.
Agent Skills spec
agentskills.io
The open format: how a SKILL.md is structured and which tools support it.
anthropics/skills
GitHub
Real examples. Reading a few of these is the fastest way to learn what a good skill looks like.
build it Turn one of the tools from your step 3 agent into a FastMCP server and connect it to Claude Desktop, Cursor or whatever you use. Then go back and clean up the skills you wrote earlier using what you now know about the format. The new skill for this step is mcp-server: how to add a tool to your server, test it and register it.
05

Tracing & evals

Agents get things wrong in ways you won't notice from a handful of manual tests. You need to see every step the agent took (tracing), and you need a repeatable way to check it's still good after you change something (evals). People skip this step a lot, and it's usually what separates a demo from a product.

tracing & observability
Introduction to Agent Observability & Evaluationsmy pick
LangChain Academy · LangSmith
Since you're already on LangGraph, LangSmith is the obvious choice. This course covers tracing, datasets, evaluators and prompt experiments. The docs are good too.
Arize Phoenixoptional
Arize · open source
An open-source alternative you can self-host. It's built on OpenTelemetry, so it works with any framework. Worth knowing if you can't send traces to a hosted service.
Langfuseoptional
Langfuse · open source
Another solid open-source option that a lot of teams use in production.
what to measure
RAG evaluators: groundedness, relevance and more
Microsoft Learn · Azure AI Foundry
Clear definitions of each metric and how it's scored. Useful even if you never use Azure. Coherence and fluency are on a separate page.
Ragas metrics
Ragas docs
An open-source library for the same kind of metrics, including agent-specific ones like tool call accuracy.
The four metrics people ask about, in plain words:
Groundedness
Is the answer supported by the sources it was given, or did the model make it up?
Relevance
Does it actually answer what was asked?
Coherence
Does it hang together and read logically?
Explainability
Can you show why the agent did what it did? For agents this mostly comes from your traces: which tools were called, with what inputs, and which documents the answer was based on.
build it Make a dataset of 20 real inputs for your agent, with what a good answer looks like for each. Run it in LangSmith with at least groundedness and relevance, change your prompt, and run it again. Write an eval-checklist skill describing what you run before calling a change done. There's an example of this one in the repo.
06

Shipping it

An agent running in a notebook isn't finished. You need an API in front of it, somewhere to store state, a simple UI so other people can try it, and a place to run it. Don't learn all of these in depth. Learn enough of each to get your agent online.

backend
FastAPI tutorialmy pick
fastapi.tiangolo.com
One of the best-written docs in Python. Do the first half of the tutorial and you'll know enough to serve an agent with streaming responses. If you're exposing tools rather than a chat endpoint, use the FastMCP server from step 4.
database
PostgreSQL + pgvector
GitHub
My default. One database handles your app data, your vectors and your LangGraph checkpoints, which is one less thing to run.
MongoDB Atlas Vector Search
MongoDB docs
A good fit if your data is document-shaped already or your team uses Mongo.
a simple frontend
Build a basic LLM chat app
Streamlit docs
A working chat UI in about 50 lines of Python. Good for internal tools and demos.
Chainlit
Chainlit docs
Made specifically for chat agents. It shows the agent's intermediate steps out of the box, which users really appreciate.
containers & cloud
FastAPI in Containers – Docker
FastAPI docs · Docker basics
Learn this before any cloud. Once your agent is in a container, deploying it is pretty much the same everywhere.
Azure AI Foundry Agent Service
Microsoft Learn
Azure's managed way to host and run agents, with evaluation and content safety built in.
Amazon Bedrock AgentCore
AWS
AWS's equivalent. It runs agents from any framework, LangGraph included, and handles memory, identity and observability.
You don't need both clouds. Pick whichever one your company (or the company you want to work for) uses. The concepts carry over.
build it Put your agent behind FastAPI, store its state in Postgres, add a Chainlit or Streamlit UI, containerise it and deploy it to one cloud. Send the link to a friend and watch them use it. Your deploy-agent skill should be the exact steps you followed, including the ones that went wrong.
07

Safety & governance

Once your agent can read untrusted input and take real actions, things can go wrong in ways that matter. In a company, someone will eventually ask you how you know it's safe. These are the resources that'll help you answer.

The lethal trifecta for AI agentsstart here
Simon Willison
Private data, untrusted content and a way to send data out. If your agent has all three, prompt injection can leak your data. A short read that changes how you design agents.
OWASP Top 10 for LLM Applications
OWASP GenAI Security Project
The standard list of what goes wrong: prompt injection, excessive agency, data leakage and more. Security reviewers will expect you to know it.
Agentic AI – Threats and Mitigations
OWASP GenAI Security Project
The agent-specific follow-up, covering memory poisoning, tool misuse, privilege issues and how to defend against them.
NIST AI Risk Management Frameworkoptional
NIST
The framework a lot of governance policies are based on. Skim it so the vocabulary is familiar when it comes up at work.
In practice, governance mostly means things you've already set up: traces so you can explain any decision (step 5), evals that track groundedness and relevance over time (step 5), human approval before risky actions (LangGraph's interrupts, step 3), and logs you keep.
build it Run your deployed agent against the OWASP list and fix the worst issue you find. Then write a pre-launch-review skill: the checklist an agent (or you) should go through before anything goes live.
08

Two more frameworks

These are worth your time even if you've been doing this for a while. They do some things better than LangGraph, and knowing them makes you better at choosing a framework.

Pydantic AI
ai.pydantic.dev
Typed, structured outputs, dependency injection and automatic retries when the model returns something invalid. It works with most model providers. If you liked FastAPI, it'll feel familiar.
Agno
GitHub · formerly Phidata
Lightweight and fast, with tools, knowledge bases, memory and multimodal input built in. It's good for getting something working quickly.

The classic on databases, streams and distributed data. The lectures above cover the theory, and this book covers how it plays out in real systems.

Frameworks change every few months. Patterns, evals and good engineering last a lot longer, so put most of your time there.
